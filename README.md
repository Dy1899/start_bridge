# start_bridge

星桥远控 0.1.5。

Windows 10/11 x64 桌面远程协助原型。使用自己的输入组件与连接服务，不依赖向日葵安装文件、账户或服务器。

## 软件版使用

解压整个软件文件夹后打开 `StarBridge.exe`。请保留旁边的 DLL 和 resources 文件夹。

先在一台电脑上双击 `Start-local-server.cmd` 启动本机测试服务，再打开两个软件窗口。默认服务地址 `ws://127.0.0.1:8787` 只用于同一台电脑测试，建议先勾选“仅允许观看”。

连接过程：输入对方 9 位识别码和 8 位临时访问码 → 被控端确认 → 被控端点击开始共享。共享时有常驻结束条；被控端可按 Ctrl+Alt+F12 断开。关闭窗口会结束远程会话。

同一路由器下的两台电脑：只在一台运行 `启动局域网服务.cmd`，两边的连接设置填写该窗口显示的同一个内网地址。详见 `docs/局域网测试.md`。内网测试使用 ws:// 连接协商，仅适合你信任的网络。

两台异地电脑需要先部署公网连接服务和 TURN 中继，再在双方“连接设置”中填相同的 `wss://域名`。详见源码包的 `deploy/部署说明.md`。本机测试成功不等于公网部署成功。

## 从源码运行

安装 Node.js 24 与 npm，在此目录运行：

```
npm ci
npm run build:native
npm run server
```

另开终端运行 `npm start`。Windows 输入组件使用系统 .NET Framework 4.x C# 编译器；不需要管理员权限。`npm test` 检查信令授权、断线清理、会话权限、坐标换算及原生组件的无操作验证模式。`npm run package:win` 生成 Windows 文件夹版。

## 画质与延迟

默认“高清流畅”：目标 1920 × 1080、60 fps，视频码率上限 16 Mbps。另提供“流畅优先”（1280 × 720 / 60 fps、8 Mbps）和“文字清晰”（2560 × 1440 / 30 fps、18 Mbps）。目标不超过被控屏幕尺寸，实际帧率和码率取决于画面变化、电脑性能与网络。

被控端可在共享前选择画质；两端都升级到 0.1.4 后，控制端也可在会话中切换。新增全屏显示、实际分辨率/帧率/码率、网络 RTT、视频缓冲和解码耗时。RTT 只衡量网络往返时间，并不是操作到画面的总延迟。

新版将普通鼠标移动与可靠的按键/拖拽通道分开，并通过序号丢弃晚到的旧位置；按键和拖拽保持可靠有序。旧版对端仍可连接，但新增功能需要双方升级。源码中对应目标参数见 ui/media-quality.mjs。

内网 ws:// 测试会给 Chromium 视频协商附加 6 Mbps 启动码率提示，缩短保守启动期间的模糊过程；随后仍由拥塞控制动态调整，不设置最低码率，不影响公网 wss:// 协商。

可运行 `node tests/media-browser-server.mjs`，再用浏览器打开 `http://127.0.0.1:18488/run?codec=auto`，或将 codec 改为 h264、vp8。该测试使用生成的画面和内存中的输入记录，不采集桌面，也不调用 Windows 输入组件；结果分别写入 runtime/performance-browser-auto.json、performance-browser-h264.json、performance-browser-vp8.json。它不能替代两台真实电脑的性能测试。

参数依据：[WebRTC 发送参数与接收缓冲](https://www.w3.org/TR/webrtc/)、[视频内容提示](https://www.w3.org/TR/mst-content-hint/)。

## 编码选择与性能报告（0.1.5）

被控端可在开始连接前选择“自动（系统默认）”“H.264 优先”或“VP8 兼容模式”。偏好会保存在本机设置中，下次共享生效；切换偏好不会重新注册设备。编码列表保留其他格式和重传格式，某一格式不可用时回退到系统默认。实际协商出的格式以会话中的性能详情为准。

两端都升级后，展开“性能详情与报告”，可同时查看被控端采集帧率、编码耗时、控制端解码与缓冲、样本丢包和每包发送排队。双方仅交换白名单内的性能字段，每秒最多一次，控制通道拥塞时跳过统计发送。实现信息和节能标志由浏览器提供；未公开的值显示“未提供”，不根据 H.264 名称推断硬件加速。

点击“保存性能报告”将最近最多 60 次采样写入程序目录 data/reports。结束会话后，主页仍可导出最近一轮报告。报告不采集访问码、IP 地址、设备名称、SDP 或屏幕画面；主进程独立筛选字段并固定保存目录。报告属于本机文件，程序不会自动上传。

编码、解码和缓冲耗时使用相邻采样的差值计算。计数器重置、第一条样本或浏览器缺少字段时保留未知值，不填成零。瓶颈提示用于辅助排查；这些分项统计和网络 RTT 都不是操作到画面的总延迟。

接口依据：[WebRTC 编码偏好](https://www.w3.org/TR/webrtc/)、[WebRTC 统计字段](https://www.w3.org/TR/webrtc-stats/)。

## 范围与限制

- 支持手动确认的屏幕共享、鼠标移动/按键/滚轮和常用键盘按键，可选系统声音。
- 不支持 UAC 与登录安全桌面、远程提权、文件传输、剪贴板同步、开机自启、无人值守或 PS5 Remote Play。
- 非美式键盘布局、中文输入法、左右修饰键、混合 DPI 多屏和系统声音需要在真实设备上进一步验证。
- 程序与输入组件没有商业代码签名，Windows 可能显示来源确认。当前为原型，不应视为成熟商业远控替代品。
- 当前未配置或部署任何公网服务。首次公网部署后，需要用两台异地电脑验证直连与强制中继。
- 配置与浏览器缓存保存在程序同目录的 data 文件夹，因此请解压到自己有写入权限的目录。

## 实现与分析来源

Electron 负责桌面界面与屏幕采集；WebRTC 负责画面和控制通道；独立 C# 组件调用 Windows SendInput；Node.js 服务协调连接；coturn 提供公网中继。

对本机向日葵文件的静态研究帮助确认了输入 API 的研究方向；本项目没有复制其伪代码、协议常量或二进制模块。

官方资料：[Electron 屏幕采集](https://www.electronjs.org/docs/latest/api/desktop-capturer)、[Windows SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)、[WebRTC](https://webrtc.org/getting-started/overview)。
