# 星桥远控 0.1.5：比较编码与定位卡顿

先把两端升级到 0.1.5，连接同一个服务。编码偏好由被控端选择，控制端的同名选项只影响它将来作为被控端时的共享。

## 建议的实机对比

1. 被控端选择“自动（系统默认）”，保持默认“高清流畅”，建立连接并开始共享。
2. 打开同一段普通视频，保持相同窗口尺寸和播放内容。避免先换网络、分辨率或帧率后再比较编码，以免混淆原因。
3. 控制端展开“性能详情与报告”，播放约 30 秒后保存报告。
4. 结束会话，在被控端改选“H.264 优先”，重新连接并重复同一段视频，再保存报告。
5. 需要时再比较“VP8 兼容模式”。记录实际协商格式，不能只根据下拉框中的偏好判断。

程序会保留最近最多 60 次采样，约一分钟。断开后，主页的“保存最近一次会话的性能报告”仍可导出；下一轮会话开始时会清空上一轮缓存。

## 如何看数据

| 显示项 | 含义 |
|---|---|
| 实际编码格式 | 本次已经协商使用的格式；编码偏好可能因对方不支持而回退 |
| 被控端采集帧率 | 浏览器报告的视频源帧率，可能未公开 |
| 被控端编码 | 最近采样间隔内每帧平均编码耗时 |
| 控制端解码 | 最近采样间隔内每帧平均解码耗时 |
| 控制端画面缓冲 | 最近采样间隔内已输出帧在抖动缓冲中的平均等待时间 |
| 接收样本丢包 | 当前采样间隔内的 RTP 丢包比例；计数不完整时不显示 |
| 每包发送排队 | 最近采样间隔内每个已发送包的平均排队时间，不能当作单帧总延迟 |
| 编码器/解码器实现 | 浏览器公开时显示其实现名称，缺失时显示“浏览器未提供” |
| 节能编解码 | 浏览器的 powerEfficient 标志，缺失时保留未知；不能仅根据编码格式推断硬件加速 |

所有耗时都是各自环节的统计，不能简单相加后声称就是键鼠到画面的延迟。测试总操作延迟仍需要两台真实电脑及对应的测量方法。

## 常见排查顺序

- 发送端报告 CPU 受限：对比编码格式，并尝试“流畅优先”。
- 发送端报告带宽受限：检查被控端上传、控制端下载，以及实际使用中继时的服务器出口。
- 解码耗时较高：降低画质或换另一种编码格式进行同场景对比。
- 丢包或缓冲较多：优先在稳定的有线网络或 5GHz Wi-Fi 下复测，再判断软件设置。
- “未提供”：可能是浏览器没有开放字段，也可能尚无有效采样；程序不会编造硬件信息或填成零。
- 未收到对方统计：检查两端版本；旧版对端仍可连接，但不提供完整的两端统计。

## 报告内容

文件保存在程序目录 data/reports，以 performance-时间-随机标记.json 命名。只保存版本、角色、画质和编码偏好，以及被筛选的性能数字和编解码实现字段，不包含访问码、设备名称、地址、SDP 或画面。文件不会自动上传。
