# 向日葵静态分析续查与自研实现

本次继续阅读上轮保留的 `sl-client-desktop.dll` 伪代码，未将“有某个 API 导入”直接视为完整实现链路。

| 函数入口 | 静态观察 | 结论边界 |
|---|---|---|
| 18036da80 | 获取或接收设备上下文，计算选定矩形的尺寸，将宽高调整到偶数；创建 32 位、负高度的 DIBSection 并选入兼容 DC。 | 可定位到一条用于像素缓冲的 GDI 初始化路径；负高度对应自顶向下的位图组织。未证明运行时总会走该路径。 |
| 18036d680 | 将一个矩形区域通过 BitBlt 从源 DC 复制到目标 DC，并返回调整后的矩形。 | 可定位局部矩形复制逻辑；具体调度关系仍需追踪。 |
| 18036d750 | 读取更新区域包围框、设置裁剪区域、调用 BitBlt、恢复裁剪并清除更新区域对象。 | 存在按更新区域进行像素复制的路径。该路径与编码、网络发送的关系仍未完全恢复。 |
| 18032d6e0 | 包装 SendInput，失败时最多重试三次，每次间隔 100 ms。 | 确认一个普通 Windows 输入 API 路径；产品内还存在其他输入后端线索。 |

这些观察来自本机安装文件的 Ghidra 静态结果，未执行目标程序。两个桌面模块的上轮自动分析达到时间限制，因此本说明仍是局部研究。

星桥远控没有复制以上伪代码、常量或原厂模块。屏幕采集采用 Electron 的系统屏幕采集接口，画面通过 WebRTC 传输；键鼠输入由独立 C# 组件调用 Windows API。公网连接协调和 TURN 中继也使用独立部署。

主屏幕采集到原厂编码器、网络传输的完整调用链，以及向日葵服务端协议，目前仍未恢复。本项目也没有实现 PS5 Remote Play。
