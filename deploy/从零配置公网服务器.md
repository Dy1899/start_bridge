# 星桥远控：从零配置公网服务器

适用情况：两台 Windows 电脑需要通过不同的网络进行远程协助。目前软件版本为 0.1.4，公网服务器尚未配置。本说明按一台新的 Ubuntu 24.04 LTS x86_64 云服务器编写；服务器的 Linux 系统不影响两台 Windows 客户端。

## 1. 准备服务器和域名

先用短期或按量实例验证，确认实际连接与画质后再决定长期套餐。下面是两台电脑自用测试的起步建议，并非经过容量压测的承诺：

| 项目 | 起步配置 |
|---|---|
| 系统 | Ubuntu 24.04 LTS，x86_64 / AMD64 |
| 处理器与内存 | 2 核、2 GB |
| 磁盘 | 20 GB 或以上 |
| 网络 | 公网 IPv4，可收发 UDP，可配置安全组 |
| 中继出口带宽 | 测试目标 20 Mbps 或以上；实际可用吞吐以实测为准 |
| 域名 | 一个能管理 DNS 记录的域名，使用 remote 子域名即可 |

服务器只协调连接、必要时转发数据，不负责把桌面画面重新编码，因此不需要为这一部署购买 GPU。

地域选在两端访问线路较好的位置，尤其要看被控电脑到服务器的上传线路。使用中国内地节点前，应先向接入商确认并办理对应的域名/应用备案要求；腾讯云的官方说明明确区分中国内地与中国香港等节点的备案场景。不要假设自用、测试或更换端口就免除其接入要求。参考：[腾讯云是否需要备案](https://cloud.tencent.com/document/product/243/19630)。

当前默认高清档位的视频码率上限为 16 Mbps；3～5 Mbps 出口的服务器即使能连接，也会限制中继画质。若一条画面持续以 16 Mbps 中继，服务器向接收端发送的视频数据约为 7.2 GB/小时，另有音频和协议开销；真实流量随画面变化。按流量计费时设置消费提醒，并核对套餐的出口限制和流量额度。不同厂商计费规则不同，例如[阿里云公网带宽说明](https://www.alibabacloud.com/help/en/ecs/public-bandwidth)。

## 2. 设置域名解析

在域名管理后台增加一条记录：

| 类型 | 主机记录 | 记录值 |
|---|---|---|
| A | remote | 云服务器公网 IPv4 |

例如你拥有 mydomain.com，之后服务地址就是 remote.mydomain.com。不要把示例域名直接用于部署。

使用 DNS 直接解析到服务器。若 DNS 服务商提供代理/CDN 开关，此记录使用“仅 DNS”或等效模式。当前方案同时用该域名提供 HTTPS 和 TURN，不应把 TURN 指向普通网站 CDN。暂不配置 AAAA，除非服务器 IPv6 也已经配置并验证。

## 3. 放行端口

在云厂商的安全组中配置以下入站规则，服务器自身的防火墙若已启用，也需要放行对应流量：

| 协议 | 端口 | 用途 |
|---|---|---|
| TCP | 22 | SSH 管理；来源限制为你的管理 IP，或使用云厂商控制台管理入口 |
| TCP | 80、443 | 自动申请证书、HTTPS 与连接协商 |
| TCP 和 UDP | 3478 | TURN/STUN 入口 |
| UDP | 49160–49200 | 本方案的 TURN 媒体中继端口范围 |

80/443、3478 和中继端口需要能被远程客户端访问。8787 只在服务器本机供反向代理访问，无需对外开放。

如果使用 UFW，先运行 `sudo ufw status` 查看现状。若已经启用，可按下面添加应用规则：

```sh
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 3478/tcp
sudo ufw allow 3478/udp
sudo ufw allow 49160:49200/udp
```

不要直接重置防火墙；本说明也不要求你开启或关闭已有防火墙。SSH 的访问规则按你的管理入口配置。

## 4. 安装 Docker Engine 和 Compose

登录服务器，在服务器终端执行。下面针对全新 Ubuntu 24.04；已有 Docker 的服务器先运行 `sudo docker version` 和 `sudo docker compose version` 检查，不要盲目重装。

```sh
sudo apt update
sudo apt install -y ca-certificates curl openssl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

添加 Docker 官方软件源：

```sh
. /etc/os-release
printf 'Types: deb\nURIs: https://download.docker.com/linux/ubuntu\nSuites: %s\nComponents: stable\nArchitectures: %s\nSigned-By: /etc/apt/keyrings/docker.asc\n' "${UBUNTU_CODENAME:-$VERSION_CODENAME}" "$(dpkg --print-architecture)" | sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker version
sudo docker compose version
```

安装依据：[Docker 官方 Ubuntu 安装说明](https://docs.docker.com/engine/install/ubuntu/)。在此部署方案中，用 sudo 执行 Docker 命令即可。

## 5. 上传部署包

将“星桥远控-公网部署包-20261020.zip”通过云厂商文件上传入口或 SFTP 上传到服务器。压缩包只包含服务端、配置和说明，不包含 Windows 客户端或访问凭据。

在上传目录解压，然后进入配置目录：

```sh
sudo apt install -y unzip
unzip '星桥远控-公网部署包-20261020.zip'
cd StarBridge-Public-Deploy/deploy
```

压缩包内的文件夹名称固定为 StarBridge-Public-Deploy。后面所有 docker compose 命令都在它的 deploy 文件夹执行。若未来换用完整 Git 仓库，同样进入仓库内的 deploy 文件夹；不要混用两份部署实例。

## 6. 填写三个配置值

```sh
test -f .env || cp .env.example .env
chmod 600 .env
openssl rand -hex 32
nano .env
```

将刚生成的随机字符串填入 TURN_SECRET。完整格式如下：

```dotenv
DOMAIN=remote.你自己的域名.com
PUBLIC_IP=服务器真实公网IPv4
TURN_SECRET=刚才生成的64位十六进制随机字符串
```

将中文说明替换成真实值，等号两边不加空格。这个共享密钥只保存在服务端；客户端会自动获得限时的中继凭据。不要把 `.env` 提交到 Git 仓库。项目已将 `.env` 加入忽略规则。

Nano 中按 Ctrl+O、回车保存，再按 Ctrl+X 退出。

## 7. 启动服务

先检查配置，然后构建、启动：

```sh
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
```

这会运行连接协调服务、Caddy HTTPS 入口和 coturn 中继。Caddy 会尝试自动签发证书，前提是 DNS 正确、80/443 可达且没有现有服务占用。参考：[Caddy HTTPS 快速入门](https://caddyserver.com/docs/quick-starts/https)。

启动异常时查看对应日志：

```sh
sudo docker compose logs --tail=100 https
sudo docker compose logs --tail=100 signaling
sudo docker compose logs --tail=100 turn
```

本部署固定 coturn/coturn:4.18.0-r0，使用 `--dtls=0`、`--cli=0`，已移除旧配置中的过时选项。依据：[coturn 4.18.0 发布说明](https://github.com/coturn/coturn/releases/tag/4.18.0)。

## 8. 验证连接服务和实际中继

在自己电脑的浏览器中打开：

```text
https://remote.你自己的域名.com/healthz
```

应得到包含这些字段的结果：

```json
{"ok":true,"version":"0.1.4","turnConfigured":true}
```

这只证明服务可访问且设置了中继配置，不能证明中继端口真的连通。

接下来在两台 Windows 客户端的“连接设置”里填写同一个公网地址：

```text
wss://remote.你自己的域名.com
```

保存后识别码和访问码会重新生成，连接时使用新显示的号码。两边不再使用原来的 ws://192.168.20.57:8788 局域网地址，也不需要运行电脑上的本机连接服务。

让两台电脑使用不同的网络，例如其中一台连接手机热点。先在两端勾选“强制使用 TURN 中继”，再发起连接，由被控端同意并开始共享。底部应包含“TURN 中继”，且能够持续看到画面并操作。

中继验证通过后，在两端结束会话、关闭强制中继并保存设置，正常使用时由 WebRTC 优先尝试直连。

## 9. 已知范围与后续维护

- 目前没有已上线的公网服务器；本包只完成配置语法检查与官方参数核对，未进行云服务器上的实际证书签发或两网中继验证。
- 本方案提供普通 TURN UDP/TCP 3478，没有 TURN over TLS 443。只允许 HTTPS 443 的受限网络可能仍无法建立画面连接，需要另外配置 TURN TLS 入口。
- 云服务器有额外 NAT、多个网卡或复杂端口映射时，按 [coturn 官方配置说明](https://github.com/coturn/coturn/blob/master/docker/coturn/turnserver.conf)核对 external-ip 的公网/私网映射。仅添加 DNS 记录无法修复 UDP 端口不通的问题。
- 容器设置了 unless-stopped 重启策略，并且 Caddy 的证书状态使用持久化卷。服务器重启后 Docker 服务正常运行时，未被手动停止的容器会恢复。
- 更新时保留 deploy/.env，再运行 `sudo docker compose up -d --build`。服务重启会断开现有会话，安排在无人连接时进行。
- 这里只面向少量自用连接；账号体系、按真实客户端 IP 的代理限流、容量监控和更广泛的公网安全审查需要后续完善。
