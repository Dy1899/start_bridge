# 公网连接服务部署

当前未部署公网服务器。以下配置面向一台有公网 IPv4 的 Linux 云服务器，使用 Docker Engine 和 Compose 插件。

1. 将本项目完整源码（包括 package-lock.json）上传服务器。
2. 给域名添加 A 记录，指向云服务器公网 IP。HTTPS 与 TURN 使用同一个域名。DNS 记录直接解析到服务器，不经过 CDN 代理。
3. 在 deploy 文件夹中将 `.env.example` 复制为 `.env`，填写 DOMAIN、PUBLIC_IP，并将 TURN_SECRET 替换为强随机值。可用 `openssl rand -hex 32` 生成；不要把该秘密填进客户端或发给连接者。
4. 在云厂商安全组和服务器防火墙放行 TCP 80、443、3478，以及 UDP 3478 和 49160–49200。80/443 用于 HTTPS 证书和连接服务；其余用于 TURN。
5. 在 deploy 文件夹运行 `docker compose up -d --build`。使用 `docker compose logs --tail=100` 查看启动结果。
6. 打开 `https://你的域名/healthz`，应返回 `ok: true` 和 `turnConfigured: true`。该状态仅确认配置存在，不能证明实际中继连通。
7. 两台 Windows 客户端填写 `wss://你的域名`。在客户端设置中勾选“强制使用 TURN 中继”进行一次测试，连接后状态应显示“当前通过 TURN 中继连接”。通过后可关闭强制中继，让软件优先尝试直连。

此 Compose 使用 Linux 的 host 网络模式，不适用于普通 Windows Docker Desktop 的默认网络模式。若云服务器位于额外 NAT 后面，需要按 coturn 的 external-ip 公网/私网映射形式调整；默认示例按可直接收发公网 UDP 的云服务器编写。

本版本提供普通 TURN UDP/TCP 3478，不包含 TURN over TLS 443。在阻断 UDP 且只允许 443 的网络中，仍可能需要额外的 TURN TLS 入口。HTTPS 本身不会自动把 TURN 流量转成 443。

服务端转发连接协商，屏幕与键鼠通过 WebRTC。连接必须提供临时访问码并由被控端本机确认。TURN 凭据由服务端签发，有效期一小时。

连接服务按小规模自用设计；反向代理后默认按其连接 IP 进行限流。扩展成多用户服务前，应补充账户、代理信任配置、监控和负载测试。

官方参考：[WebRTC TURN](https://webrtc.org/getting-started/turn-server)、[coturn](https://github.com/coturn/coturn)、[Caddy](https://caddyserver.com/docs/)。
